seam carving

Content-aware image resizing: instead of scaling every pixel, this finds the least-important connected path of pixels running top-to-bottom (or side-to-side) through the image and removes it — or, to grow the image, duplicates it — one seam at a time. Busy areas survive; empty sky and flat walls move first. Based on Avidan & Shamir's 2007 seam-carving paper — energy function and dynamic-programming seam search, reimplemented here from the well-documented algorithm, running entirely in this tab on whatever you upload.

what this is actually doing

Every pixel gets an energy score — here, the magnitude of the brightness gradient, so edges and texture score high and flat regions score near zero. A seam is a connected path of one pixel per row (or per column), stepping at most one pixel left or right as it goes, that minimises the total energy it crosses — found with the same dynamic-programming trick as edit distance: for each pixel, add its own energy to the cheapest of the three seams that could have reached it from the row above, then walk the cheapest path back down. Removing that one path shrinks the image by exactly one pixel in that dimension, with (ideally) no visible seam, because it was already the least interesting connected path there was. Do it a few hundred times and boring width disappears while faces, horizons, and high-contrast objects hold their shape — which is the opposite of what a plain scale or crop does.

Growing an image (target > 100%) works the other direction: instead of finding one seam and deleting it, the same search runs repeatedly on a shrinking scratch copy to pick the k least-important seams without touching the real image, remembering where each one sits in the original — then all k get duplicated back into the real image in one pass, spread out by index so they don't all pile up on one edge. Duplicated pixels are averaged with their neighbour rather than copied exactly, which softens the seam. Large single-pass enlargements duplicate more per seam and can start to look smeared; the paper's fix is running it twice in smaller steps, which isn't built here yet.

Large or very tall/wide images are downscaled first so the browser tab stays responsive — carving is O(seams × width × height), recomputed from scratch after every single seam.
