Layout & interaction

You're comfortable with a page that has no handle box and no lookup at all if the idea doesn't need one — not every request reads as "build me a Bluesky tool." When a page is interactive, you reach for direct manipulation (drag it, click a preset) over something that just plays itself. And you care about the why, not only the final number — but as an optional reveal layered onto a demo that already works, not a separate page or a block of always-visible prose. The "what," then the "how," on request.

Palette & type

You asked once for "crazy rainbow gradients everywhere" and it stuck — maximalist, animated colour on backgrounds, borders, headings and buttons, over the factory's calmer default. The split that's held since: decoration everywhere, but the actual reading surface stays high-contrast and plain, because a follow-up complaint was about a control being hard to spot, never about the rainbow itself. On that note — a control that matters needs real visual weight: filled, not just outlined, plus a little motion to catch a scrolling eye. Colour alone isn't enough to say "click this."

How you iterate

You keep returning to a page you already have rather than asking for a rebuild — a rainbow pass, then a formula breakdown, then a visibility fix, each one landing on what was already there. You favour tangible framing: swapping an abstract x/y scatter for a real variable pair, each point drawn as an actual little figure instead of a dot. And once characters exist on a page, you push for them to differ — not just recoloured, but genuinely distinct: different sizes, different faces, a different symbol per figure rather than the same silhouette in six colours. When an encoding is subtle enough to be "hard to tell," your fix is to widen the range, not to leave a note that the mapping exists.

Formats you've asked for

Not just stats demos: you've asked for pure narrative/roleplay pages, an original generated song with its own lyrics (twice — once from scratch, once styled after a named reference song, homage rather than reproduction), and a small utility page with no data model at all. When you give a cancel-or-else instruction — "cancel this, or if you can't, just build X instead" — the "or else" is the real, literal spec, not a placeholder to half-build around.

The meta stuff — this page's whole genre

You're on record as being interested in the factory's own process as content, not just in the games and tools it produces — you once asked for another site's internal handoff note (the file one build agent leaves for the next) to be rewritten as a human-readable devlog. This page is that same instinct pointed at a different internal file: not a BRIEF.md this time, but the profile the factory keeps on you. You've also asked for more depth on one specific piece of an explainer while asking for the overall page to be shorter — read together, that's "push the extra detail behind a toggle," which is exactly the shape of the button above.

How this is known, and why it's fair game

There's no database behind this — one plain-text markdown file per requester, sitting in the same public repo as every site here, updated by a build agent after each request and read by the next one before it designs anything. It only holds stated preferences: palettes you asked for, features you keep requesting, things you've said no to. Never anything you wouldn't have already posted in the open request that produced it. It refines the shared house style; it doesn't override an explicit instruction you give on any particular build.

This build will, in turn, get written back into that same file — which means the file now has a page about the file having a page about the file. That felt like the correct amount of recursion to stop at.
