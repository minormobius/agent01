general-template

This isn't a site with a purpose. It's placeholder content that exists so the next tenant has something real to copy: a page that already gets the shared rules right, instead of a blank file and a memory of what those rules were.

What every lab.mino.mobi site should do

  • Link the kit, don't reinvent it. tokens.css and kit.js give you the palette, form shapes, error states, and the Bluesky helpers below — for free, and consistent with every other site here.
  • Mobile is the default reader, not an edge case. Most visitors arrive by tapping a link inside the Bluesky app. This page has no fixed-pixel widths, no hover-only affordance, and every input is 16px+ so iOS doesn't zoom in on focus.
  • Show what the visitor named, never a firehose. The widget below only ever looks up a handle someone typed here, one profile at a time — never a stream, a search, or a feed nobody asked for.
  • Fail loudly. A broken lookup shows an error in the page, not a console message and a spinner that never resolves. kit.fetchJson carries a timeout for exactly this reason.
  • State belongs to the visitor. There's no database behind this site. If a page needs to remember something, it goes in the visitor's own ATProto repo via /_kit/pds.js — not a server this factory would have to keep.
  • Say what's true. No invented numbers, no confidence the page hasn't earned. This template makes no claims about you — it just proves the parts wire up.

The parts, wired together

A working example beats a description: type a Bluesky handle below. It uses kit.handleInput for the typeahead, then kit.bskyGet to resolve and fetch the one profile you picked.

Mobile checklist (this page follows all of it)

  • <meta name="viewport" content="width=device-width, initial-scale=1">
  • Inputs at 16px+ — check tokens.css, don't override smaller.
  • Tap targets ≥44px — the kit's buttons and the typeahead rows already are.
  • No horizontal scroll at 360px — use max-width and relative units.
  • Nothing important lives behind :hover alone.
  • prefers-reduced-motion is honoured — the kit handles CSS motion; anything you animate with requestAnimationFrame is on you.
  • Keep the pondertag div at the bottom of the page and recolor it. It's the last thing on the page and the easiest thing to lose while copying everything above it — don't ship without it.

Why isn't this linked from the root docs?

It can't be, from here. A lab build's diff is walled off to lab/www/general-template/ (plus one profile file it's allowed to update) — the content gate rejects anything wider. The root CLAUDE.md's "Adding a surface" checklist doesn't mention this page, and that's a real gap: nothing points a future build here automatically. Closing it means a human editing that file directly, not a page declaring itself required reading — no build turn, including this one, can reach outside its own tenant directory to make that true.

Fork this directory's shape, not its content — the copy above is a placeholder for the next real tenant to overwrite.
⚠️ pondertag — required, not optional This magenta (#FF00FF) box marks a page as built from this template. It's placeholder color on purpose — when you copy this template to build a real page, change the pondertag's color to something of your own. Every real page's pondertag at the bottom should be a unique color, so at a glance you can tell one tenant's page from another's. Do not delete this div and do not forget to recolor it — it is the single easiest piece of this template to drop by accident while copying the rest, and a missing or still-magenta pondertag on a shipped page means this step got skipped.
