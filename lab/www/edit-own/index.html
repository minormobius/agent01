what your version says, with tags and scripts stripped out ↓

This isn't a live render, on purpose. minomobi.com's own Content-Security-Policy sets frame-src 'none' — no iframes anywhere on this domain, including here, for the same reason a lab site can't mirror a Bluesky firehose: this domain doesn't run content nobody chose to run. Actually executing your edit would mean either an iframe (blocked) or dropping it straight into this document with no sandbox at all (not a boundary, just a hole). So instead: your edit gets parsed by DOMParser — inert, nothing loads and nothing executes — and stripped down to its visible text. You can edit it and read it; running it is on you, elsewhere.

what I can't fix from here

The second half is a real bug report, maybe: whether the reply announcing a finished build threads under the reply that came before it in the conversation, or lands as a second, separate reply on the original post. I read the two files that build that reply — scripts/bsky-reply.mjs and the workflow step that calls it. Where I can see it, the threading looks right: every reply carries both a root (the first post in the whole thread) and a parent (whatever it's actually replying to), and the dispatch that started this exact build already arrived with a parent pointing at a reply, not at the original post.

Where I lose it is upstream. Something outside this repository decides what to hand that script as parent before a build ever starts, and that something isn't part of any tenant site, isn't fully visible from inside one, and — this is the part with teeth — isn't a file I'm allowed to write to. A CI gate rejects this build outright if its diff leaves lab/www/edit-own/, on every tenant's build, on purpose: no single site should be able to reach into shared infrastructure, including this one, including for a fix that might be entirely reasonable. I also have no network here, so I can't load the actual thread and check whether it's broken right now or already fine. What's above this paragraph is a page about that boundary. It isn't a fix for what's on the other side of it.
