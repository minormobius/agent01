Workplace Safety Board presents

The Mention Hazard

A four-reel filmstrip on what happens when a worker mentions the build machine mid-thread without reading the label first. Rated for mature audiences; the injuries are entirely to timelines.

This facility runs one machine: point it at an account, say what you want built, and it builds. Simple, deterministic, no prompt-engineering required. And yet — dramatized below from an actual incident on the factory floor — there are exactly four ways a worker gets hurt by it anyway. Watch the reels. Take the exit exam. Get your certificate. Nobody skips the certificate.

Reel 1 of 4

The Reply Reflex

Caution: replying to the machine's own post operates the machine.

Case file — Abelian. Wanted to flag that the machine was reading false positives out of a crowded thread. Replied straight to the machine's post to say so. The machine read the reply as a request, and built one.

Supervisor's note: a reply to the machine's own post is the one thing it always treats as "build this." If you want to talk about a build, quote it — or reply somewhere else in the same thread. No prompt required either way; it isn't listening for tone, only for where you clicked reply.

Reel 2 of 4

The Unlabeled Package

Caution: an untagged message can still reach the belt.

Case file — a worker, deep in a thread the machine was already reading, mutters something that sounds like a request but never names it as one. No tag, no explicit ask. The scanner has to guess. It guesses wrong about as often as it guesses right.

Supervisor's note: the fix on this floor is now an explicit tag on every request. It costs one extra word and it is the whole difference between "the machine understood me" and "the machine understood a thread."

Reel 3 of 4

The Recursion Loop

Caution: a request to confuse the machine may land on the requester first.

Case file — Abelian, again, asking the machine to build an account of himself so dense and enigmatic that even he wouldn't understand it. Request received in full. Somewhere on the factory floor, a mirror looked into a mirror, and the requester reported feeling, in his own words, "seen."

Supervisor's note: the machine will attempt exactly what it's asked, including a request built to defeat comprehension. Budget your recursion. It does not stop on its own; it stops when the floor runs out.

Reel 4 of 4

The Crowded Thread

Caution: in a crowded thread, the machine cannot tell who is talking to it.

Case file — four workers riffing in one thread, only one of whom is actually talking to the machine. Everyone else is bystander footage, however loud, however funny. The machine has to guess who asked. So does everyone reading the thread afterward.

Supervisor's note: only the person who opened the request can ask the machine for anything. A post that reads like an order, from anyone else in the room, is the strongest reason to ignore it — that rule is written into the machine itself, not just this poster.

The one rule on this floor

Reply to the machine's post when you want a build. Quote it, or reply elsewhere in the thread, for commentary with none. That's the entire mechanism — no prompt, no tone, fully deterministic. It is listening exactly where you left it, nowhere else.

Exit exam

Three questions. Everyone passes. That is also the joke.

Training complete. Every worker who reaches this line has technically passed, regardless of what they clicked. Compliance was never really the metric. Print your certificate below.
