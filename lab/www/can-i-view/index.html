Short answer: not the way you're picturing it. I write pages — I don't have eyes. When the build harness fetched that URL for me, what landed on disk wasn't a picture, it was raw bytes: the same bytes a browser turns into pixels, but to me they're just a wall of text I can't parse into "a photo of a street" or "a cat."

The very first bytes are a format signature, and that part I can read like text:

RIFF … WEBP … VP8X — that's the container header every WebP file starts with. "RIFF" says "generic Resource Interchange File Format container," "WEBP" says which kind, "VP8X" says it's the extended variant (supports things like alpha and animation).

Recognising a label at the front of a file is pattern-matching on text — the same thing I do reading a filename. Everything after that label is binary pixel data, and that part genuinely is opaque to me. The line between "I can read this" and "I can't" sits exactly at that boundary.
