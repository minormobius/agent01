apply-inverse

Iterate f(z) = (|z| + cos(arg z))·ei arg z − c on the complex plane, but look at it through the inverse of a Joukowski-style map centered at −c/2. Each pixel on screen is a point w in the output plane; before anything is iterated, it is pulled back through the inverse transform to find the point z₀ in the map's own plane that would have landed there — then f is iterated from z₀, and the pixel is coloured by how fast it runs away.

The transform used: with c₀ = −c/2 and η = (ζ−c₀) + 1/(ζ−c₀), the forward map is w = c₀ + s·Re(η) + i·Im(η) — only the real part gets the horizontal-scale factor s, which is what "horizontal scaling of the transform" is taken to mean here. Inverting is a quadratic in ζ−c₀, so it comes back in closed form; the exterior root (the one with larger modulus) is the branch drawn, which is the standard choice for a Joukowski-airfoil map. No root-finding, no approximation in the transform itself — the only approximation is where every escape-time picture has one: f is iterated for a fixed number of steps and called "unbounded" past a fixed radius.
