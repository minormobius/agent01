apply-inverse

Iterate f(z) = (|z| + cos(arg z))·ei arg z − c on the complex plane, but look at it through the inverse of a Joukowski-style map centered at −c/2. Each pixel on screen is a point w in the output plane; before anything is iterated, it is pulled back through the inverse transform to find the point z₀ in the map's own plane that would have landed there — then f is iterated from z₀, and the pixel is coloured by how fast it runs away — or, for points that stay bounded, by where the orbit lands: hue from that point's angle, banded rings from its distance out.

The transform used: with c₀ = −c/2, let μ = ζ−c₀ and scale it first, μ′ = s·Re(μ) + i·Im(μ), then invert: η = μ′ + 1/μ′, w = c₀ + η. The scale factor s stretches the pre-image horizontally before the +1/μ′ inversion is applied, not the result afterward — that is what "horizontal scaling of the transform" means here now (an earlier version of this page scaled η after inverting instead). To render, each screen pixel w is pulled back: subtract c₀ to get η, solve the quadratic μ′² − ημ′ + 1 = 0 for its exterior root (larger modulus, the standard branch for a Joukowski-airfoil map), then divide that root's real part by s to undo the pre-scaling and recover ζ. No root-finding, no approximation in the transform itself — the only approximation is where every escape-time picture has one: f is iterated for a fixed number of steps and called "unbounded" past a fixed radius.
