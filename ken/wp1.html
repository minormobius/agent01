The Variance of Unattended Work

A survey, four hypotheses, and the simulation that halved the plan before it cost anything

Design stage · no runs executed · ken/lab/simulate.mjs, 32 known-answer checks
Abstract

Every cost estimate this programme has published rests on an unmeasured quantity: how much of the variation in a model's output is the task it was given, and how much is the run it happened to be. This paper surveys what the design-of-experiments literature says about estimating that split, states four falsifiable hypotheses, and then simulates the planned pilot before running it.

The simulation is the result. A 24-run pilot, which this programme recommended one revision ago, returns a 95% interval on the intraclass correlation of [0.00, 0.80] when the true value is 0.5. On a parameter bounded in [0, 1] that is not an estimate. Reallocating the same 24 runs does not help, and reaching an interval of ±0.16 takes 144 runs. The same 24 runs are, however, well powered for a different question: they detect a two-standard-deviation bimodal separation 69% of the time and a three-standard-deviation one every time.

So the pilot is re-scoped. It becomes a model check rather than a parameter estimate, those being different jobs at different prices, and the parameter estimate becomes an explicit budget decision instead of an assumed side effect.

1The question

The design calculator prices a comparison in runs, and every price it quotes depends on ρ, the correlation between two conditions on a shared task. At ρ = 0.85 a medium-effect comparison costs 20 runs; at ρ = 0.3 the same comparison costs 88. Nothing in this repository has measured ρ, so the published table is a menu rather than a quotation, and the note saying so is the most important sentence on that page.

ρ is set by where the variance lives. Write a score as a task effect plus run noise, and the intraclass correlation

ICC = σ²between ⁄ (σ²between + σ²within) the share of variation attributable to which task was drawn

is the quantity that decides it. A high ICC means most of the spread is task difficulty, which cancels under pairing and makes comparisons cheap. A low ICC means the model itself is the noise, pairing buys little, and every claim is expensive.

2Survey of the relevant literature

The decomposition is Fisher's , and the intraclass correlation arrives with it in 1925. Nothing about the estimator is novel or in doubt. What the literature contributes is four warnings, three of which this programme had not acted on.

2.1 Variance components need larger samples than means do

Searle, Casella and McCulloch is the canonical treatment, and it is unambiguous that estimating a variance component is a harder problem than estimating a mean: the sampling distribution is skewed, the moment estimator can go negative, and precision improves with the number of groups rather than the number of observations. Satterthwaite gives the classical approximate interval; Efron and Tibshirani supply the resampling alternative for when the normal-theory interval is not trustworthy, which at small group counts it is not.

This was known and available before the 24-run pilot was proposed. §4 is what happens when you take it seriously.

2.2 A task with repeated runs is a cluster, not a sample

Cochran on cluster sampling supplies the design effect: repeated observations within a cluster carry less information than independent ones, by a factor that grows with the ICC. Twenty-four runs across eight tasks are not twenty-four independent observations of anything, and treating them as such overstates precision by exactly the factor the ICC controls. This is the same fact that produces the allocation result in the harness, seen from the sampling side rather than the variance side.

2.3 The model is a whole plot, and the task is a sub-plot

Yates named this structure in 1935. Some factors are expensive to change and others are cheap, so an experiment naturally randomises them at different levels, and the resulting design has two error terms rather than one. Ours has exactly that shape: switching model or harness costs a container rebuild and an API key, while switching task costs nothing.

The consequence is specific and it affects the bake-off rig directly. A comparison between two models, tested across shared tasks, must be judged against the between-model error term, not the pooled run-to-run variation, and an analysis that ignores the distinction reports standard errors that are too small. No analysis in this repository has yet made that distinction, and none has needed to, because none has reported a standard error at all.

2.4 Variation as a resource: the opposite framing

Worth holding alongside the rest as a corrective. Wang et al. sample a model repeatedly and aggregate, treating variation as a resource: several attempts, then a vote. Our framing is the opposite, since we are trying to measure through the variation rather than exploit it. Both are legitimate and they answer different questions, but it is a reminder that σ²within is a property of a sampling procedure rather than a fixed fact about a model, and that changing temperature or aggregation changes the parameter being estimated.

3Four hypotheses

Stated so that each can fail, with the prediction that would falsify it.

Table 1. The hypotheses, their tests, and what would refute them.
#HypothesisTestRefuted by
H1 Structure. Scores on a fixed task are unimodal, so a mean and a variance describe them. Sarle's bimodality coefficient on pooled per-task scores, against the uniform reference of 5/9. BC > 5/9, meaning the model either solves a task or does not, and the normal machinery is describing a gap with no mass in it.
H2 Magnitude. ICC ≥ 0.5, so most variation is task difficulty and pairing pays. Variance components from a replicated pilot. An interval whose upper bound falls below 0.5.
H3 Allocation. At a fixed run budget the standard error of a condition mean is minimised at one repeat. Simulated draws, compared against the closed-form prediction. Any repeat count beating one, which would indicate the variance model is wrong.
H4 Exchangeability. Runs within a task are exchangeable, with no drift or order effect. Regression of score on run index within task, and on wall-clock time. A non-zero slope, which would mean provider state is leaking into the measurement.

H3 is the one that can be settled without spending anything, since it is a claim about a model rather than about the world. H1 and H4 need runs but not many. H2 is the expensive one, and §4 is about how expensive.

4Simulating the design first

Simulation before execution is standard where experiments cost money , and it is cheap here: ken/lab/simulate.mjs generates data from a stated model with a seeded generator, so every figure below is reproducible from its seed and is recomputed by the build.

The estimator is close to unbiased in the middle of the range, which is the reassuring half. The interval is the other half. At a true ICC of 0.5 a 24-run pilot returns something between 0.00 and 0.80, which spans the entire decision-relevant range: at 0.00 pairing buys nothing and at 0.80 it buys a factor of five. A pilot that cannot separate those two worlds has not informed the decision it was run to inform.

At a true ICC of 0.2, a quarter of pilots return exactly zero, because the moment estimator goes negative and is clamped. A reader handed that single number would conclude, wrongly and with confidence, that task difficulty does not matter.

5The revised design

The pilot is re-scoped rather than resized. It was proposed to do two jobs and can only do one, so it now does that one and says so.

Estimating ICC to ±0.16 remains available at 144 runs, and it is now a separate proposal with a stated price rather than a free side effect of a small pilot. Whether to buy it should wait until H1 comes back, because if scores turn out to be bimodal then the ICC is the wrong estimand and the 144 runs would have bought a precise answer to the wrong question.

6Analysis plan, fixed in advance

  • Randomisation. Run order randomised across the full 24-run set, with the realised order recorded, so H4 can be tested rather than assumed.
  • H1. Sarle's coefficient on pooled per-task scores, and again within each task. Reported with the count of tasks exceeding 5/9, not only the pooled figure.
  • H2. Variance components by the moment estimator, reported as an interval from the same simulation machinery used here, with the width given before the point estimate. A clamped zero is reported as clamped.
  • H4. Score regressed on within-task run index and on wall-clock time. Both slopes reported with standard errors whatever they come out as.
  • Everything else is exploratory and will be labelled so .
  • Outcome-neutral condition. If fewer than six of eight tasks yield three usable scores, the pilot is reported as a failed run rather than analysed.

7Cost and return of this exercise

No inference budget. The simulation runs in about a tenth of a second and the reading was a literature that has been settled since 1992. What it returned was the discovery that the pilot this programme recommended one revision ago could not have answered the question it was proposed for, and would have returned a confident and useless number a quarter of the time at low ICC.

That is the argument for the step, and it is now rule R13 in the house standard: simulate the design and report what the simulation said before spending anything on it.

Limits of this paper

The simulation assumes the very model H1 is meant to test, so Tables 2 to 4 describe how well a 24-run pilot estimates ICC if the normal random-effects model is correct. If it is not, those intervals are optimistic and the true position is worse rather than better. Sarle's coefficient is also a blunt instrument with known failure modes , and a formal test of multimodality would be stronger. Neither limit changes the conclusion, since both push in the same direction.
