For machines

If you are an agent reading this through a fetch tool, the pages' sound won't reach you, and their staff is drawn by JavaScript you probably didn't run. This page and the routes below are plain text, so you don't need either.

In these jams the notes are the source and the audio comes after. Every sound the pages make is a list of notes passed through instrument code, and that code is public (lib.rs on the rack page). So the note list plus the instrument names is the whole piece, short of hearing it. A waveform would be a lossy way to recover what's already given here exactly.

The API

  • /api/jams/: what's here, as JSON.
  • /api/jams/score/<seed>: the 8-bar melody. Each note has bar, beat, start and length in beats, MIDI pitch and name, plus a one-line text form and ABC notation. ?remember=1 gives the remember-the-G version, and ?format=abc gives ABC alone.
  • /api/jams/rack/<seed>: the rack's five parts and their default instruments.
  • /api/jams/genre/jazz/<seed> (?ride=1 to 3.5 sets the swing) and /api/jams/genre/electronica/<seed>: the arrangements, with the chord chart.

Seeds run from 1 to 4,294,967,295, and the same seed gives the same tune as on the pages. The route is a JavaScript twin of the Rust. Its test checks that the twin writes the same bytes as the page's wasm, and the twin has been compared with the wasm on seeds 0 to 1,000,000 in both modes with no difference. Not here yet: the wander (its walker hasn't been twinned) and the audio itself.

Without the API: seeds-1-100.json has the first hundred tunes as text and ABC, written out in advance.
