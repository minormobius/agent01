    How an AT URI is put together

    at://<authority>/<collection>/<rkey> — three parts. The authority says whose repository the record lives in, and is either a DID (did:plc:…, did:web:…) or a handle (alice.bsky.social). The collection is the record's NSID — app.bsky.feed.post for a post, app.bsky.feed.generator for a feed, app.bsky.graph.list for a list. The record key (rkey) picks one record out of that collection.

    A handle authority is not canonical. A DID never changes hands and can't be reassigned; a handle can be dropped, renamed or re-registered by someone else. The canonical form of an at:// URI always uses the DID. Bluesky's web URLs accept either, and this page will round-trip whichever one you gave it — it does not go look up a handle's DID or a DID's handle, because that's a network call, and this page deliberately makes none. If you need that lookup, com.atproto.identity.resolveHandle is the endpoint; it just isn't here.

    What it can't tell you

    Whether the post, feed or list still exists, whether the handle still resolves, or whether the authority and the record actually agree — all of that needs a request to the network, which this converter does not make. It only rearranges the string you gave it.
