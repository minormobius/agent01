How an AT URI is structured

at://<authority>/<collection>/<rkey> — the authority names the repo (a DID, or a handle that still needs resolving), the collection is the record's NSID (app.bsky.feed.post for an ordinary post), and the rkey is that record's key inside the collection. A bsky.app permalink is the same three things spelled out as a web path instead.

A handle authority is not canonical. at://alice.bsky.social/… and at://did:plc:xyz…/… can name the very same record, but only the DID form is canonical — a handle can be repointed to a different account later, a DID never changes. Turning one into the other means resolving the handle (com.atproto.identity.resolveHandle), which is a network lookup this page deliberately does not make. If you paste a handle authority, the conversion still works — it's just not the canonical form.

Recognised collections here: app.bsky.feed.post (post), app.bsky.feed.generator (feed), app.bsky.graph.list (lists), app.bsky.graph.starterpack (starter-pack). Anything else parses fine — you'll just get the breakdown, not a bsky.app link, since this tool doesn't know that collection's URL shape.
